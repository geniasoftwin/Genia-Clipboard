# Security notes — GeniaClipboard 0.4.4

Проверка обновлена 22 августа 2026 года.

## Что проверено и усилено

- Нет сторонних `PackageReference`: приложение использует только .NET/WinForms и WinAPI.
- Build-скрипт переключает `cmd.exe` на UTF-8 до вывода русских сообщений; изменение касается только отображения текста и не ослабляет параметры публикации.
- Build-скрипт выполняется из каталога проекта (`pushd`) и использует относительные пути для `dotnet publish`, выходной папки и ZIP; это предотвращает разбор пробелов полного пути как отдельных MSBuild-аргументов.
- Self-contained публикация зафиксирована на .NET Windows Desktop Runtime 8.0.30 — августовском security patch 2026 года.
- Внутреннее копирование GeniaClipboard помечается приватным clipboard-format и не попадает обратно в историю или TXT-журнал.
- Служебные подписи интерфейса используют отдельный `NoCopyLabel`, который подавляет штатное WinForms-поведение копирования текста Label по двойному клику. Это не только предотвращает самонакопление, но и не позволяет таким кликом затереть пользовательский буфер.
- Резервный polling использует `GetClipboardSequenceNumber`, а не хранит вторую копию последнего текста.
- Размер одной сохраняемой записи ограничен 1 000 000 символов.
- Размер загружаемого `history.json` ограничен 64 MiB; чрезмерно большой или повреждённый файл не загружается.
- Размер пакетного копирования ограничен 16 000 000 символов, чтобы уменьшить риск зависания/OutOfMemory.
- Множественный предпросмотр ограничен 200 000 символов.
- TXT-экспорт выполняется потоково и не объединяет всю историю в одну дополнительную строку в памяти.
- История сохраняется во временный файл с последующей заменой; поток принудительно сбрасывается на диск перед заменой.
- Перед автоматической отправкой `Ctrl+V` проверяется, что нужное окно действительно стало foreground-window. Это предотвращает вставку в случайное приложение при отказе `SetForegroundWindow`.
- Пути автоматического журнала формируются приложением внутри `Data\Journal`; имя файла не строится из содержимого буфера.
- Ручной экспорт использует системный `SaveFileDialog`, ошибки доступа/ввода-вывода обрабатываются.

## Остаточные риски

- История, `settings.json` и TXT-журнал не шифруются. Любой пользователь/процесс с доступом к папке приложения может прочитать эти файлы.
- Менеджер буфера не может надёжно определить, является ли скопированный текст паролем, API-ключом или другой тайной. Для таких операций следует временно отключать сбор.
- Любой процесс в пользовательской сессии Windows в принципе может читать/изменять системный буфер обмена; private clipboard-format не является границей безопасности, он нужен для предотвращения самодублирования.
- Глобальная автоматическая вставка использует WinAPI и зависит от правил foreground activation Windows. При невозможности безопасно подтвердить целевое окно вставка отменяется.
- .NET 8 заканчивает поддержку 10 ноября 2026 года. До этой даты следует запланировать переход на .NET 10 LTS и повторную проверку.

## Проверка сборки

В текущем рабочем окружении отсутствует .NET SDK, поэтому фактический `dotnet build/publish` здесь выполнить невозможно. Перед релизом на Windows необходимо:

1. установить актуальный .NET SDK / Visual Studio;
2. выполнить `build-portable.cmd`;
3. проверить сценарии `Ctrl/Shift` multi-select, `Ctrl+A`, batch copy, export и auto-journal;
4. проверить, что после копирования из самой GeniaClipboard количество записей не меняется;
5. повторить сборку после каждого обновления `RuntimeFrameworkVersion`.

## 0.4.4 build hotfix

Сборочный скрипт больше не передаёт MSBuild абсолютный publish/output-путь через `-o`. Это устраняет ошибочное разбиение путей с пробелами и уменьшает зависимость сборки от особенностей разбора аргументов командной строки.
