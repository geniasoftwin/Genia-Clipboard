# Черновик для Хабра — НЕ ОПУБЛИКОВАН

# Зачем писать ещё один менеджер буфера обмена для Windows, если уже есть Ditto?

История буфера обмена — из тех функций, которые начинают ценить только после того, как один раз потеряешь нужный текст. В Windows уже есть Win+V. Есть зрелые open-source инструменты — Ditto и CopyQ. Поэтому вопрос к новому приложению совершенно справедливый: **зачем ещё одно?**

Мы развиваем [GeniaClipboard](https://github.com/geniasoftwin/Genia-Clipboard) — небольшой менеджер *текстовой* истории буфера для Windows 10/11 на C#, WinForms и .NET 8. У проекта открытый исходный код и MIT License. Мы не претендуем на превосходство над Ditto по количеству возможностей. Задача проще: понятный portable-инструмент без аккаунтов, облака и телеметрии, в котором пользователь контролирует сохранение текста.

## Главная техническая проблема — сохранение чувствительного содержимого

Традиционный clipboard-history удобно записывает всё подряд. Но в буфере оказываются не только URL и фрагменты кода, а иногда токены, данные учётных записей и сообщения.

Мы начали с обычного JSON, но быстро увидели, что plaintext-история для инструмента, который работает постоянно, — плохой выбор. Поэтому в версии 0.5.x появилась система vault.

### Два режима хранения

**Windows Vault.** История шифруется AES-256-GCM, а случайный ключ защищён DPAPI текущего пользователя Windows. Пользователь не вводит пароль при каждом запуске, но такой vault привязан к Windows-профилю.

**Portable Vault.** Ключ получается из мастер-пароля через PBKDF2-HMAC-SHA256. Это позволяет переносить зашифрованную историю между ПК. Пароль не сохраняется в настройках; его потеря означает потерю доступа к данным.

Формат хранилища версионирован и содержит nonce, salt (в Portable-режиме), тег аутентификации и ciphertext. При миграции с предыдущего plaintext-формата приложение сначала создаёт encrypted vault и проверяет его расшифровку, а уже потом удаляет прежний файл.

Важно: шифрование **не защищает от malware**, уже работающего в том же пользовательском сеансе и читающего память процесса либо системный clipboard. Не стоит превращать слово «encrypted» в обещание абсолютной безопасности.

## Clipboard Firewall и Private Session

GeniaClipboard умеет исключать выбранные процессы из захвата, учитывать Windows clipboard privacy-маркеры и распознавать некоторые высоковероятные форматы секретов. Обнаруженные записи можно автоматически удалять по таймеру.

Для временной работы предусмотрен **Private Session**: история живёт только в памяти, не попадает в постоянный vault и автоматический TXT-журнал.

Но и здесь есть границы. Определение источника и секретов работает с ограничениями Windows API и эвристическими правилами. Никакой гарантии выявления любого пароля нет.

## Неожиданная сложность: «Вставить» — это не то же самое, что «Копировать»

Менеджер может легко скопировать текст в clipboard. А вот автоматически вставить его в исходное окно — более сложная задача. WinForms теряет фокус, Windows может не разрешить переключить активное окно, а пользователь может открыть интерфейс через хоткей, трей или панель задач.

Мы несколько раз меняли поведение после реальных тестов: отказались от повторного использования старых выделений, добавили проверку идентичности целевого окна и его процесса, а затем перешли к отслеживанию последних активных внешних окон через Win32 `SetWinEventHook`.

В 0.5.6 мы тестируем единое правило: независимо от способа открытия интерфейса кнопка «Вставить» ищет недавнее внешнее окно, проверяет его перед отправкой Ctrl+V и не отправляет клавиши, если безопасной цели нет. Предыдущие выделенные строки при следующем запуске окна не сохраняются — чтобы Enter не повторял старую вставку.

Это пример UX-ошибки, которую сложно предугадать только по коду. Скриншоты и живые тесты оказались полезнее предположений.

## Что умеет проект и чего пока не умеет

Сейчас доступны поиск, закрепление, множественное выделение, редактирование записей, настраиваемый хоткей, опциональный автозапуск, локальные настройки и ручной TXT-экспорт.

Пока **не поддерживаются** изображения, копирование файлов, HTML и RTF. TXT-журнал и TXT-экспорт остаются незашифрованными — это явно указано в документации. Бинарные файлы пока не имеют Authenticode-подписи.

Нужна ли следующая ступень с преобразованиями текста? Есть идея добавить очистку tracking-параметров в URL, JSON pretty/minify, смену регистра, trim и обработку строк. Но прежде хочется проверить с пользователями базовый сценарий: копирование → поиск → вставка.

## Как попробовать и помочь

Код и релизы: https://github.com/geniasoftwin/Genia-Clipboard

Лицензия: MIT. Платформа: Windows 10/11 x64. Сборка портативная; на целевой машине не требуется установленный .NET runtime.

Сообщения об ошибках и предложения: https://github.com/geniasoftwin/Genia-Clipboard/issues

Если будете тестировать, используйте вымышленные строки. Не публикуйте реальные пароли, токены, файлы vault и снимки личного clipboard.

Мне особенно интересны три вопроса:

- Насколько предсказуема вставка в Notepad++, браузер и редакторы кода?
- Нужны ли два режима vault, или настройка воспринимается как лишняя сложность?
- Какие операции с текстом вы выполняете в clipboard чаще всего?
